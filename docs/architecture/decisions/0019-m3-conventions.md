# ADR-0019: M3 conventions: RLS wiring, database test infrastructure, pagination, OpenAPI, and API compatibility

- Status: Accepted (2026-10-21 by the user)
- Date: 2026-10-21
- Owners: TenantFlow tech lead (options recommended by Claude, chosen and accepted by the user on 2026-10-21)
- Related decisions: ADR-0011, ADR-0012, ADR-0015, ADR-0016, SPEC-0003
- Closes: Open Decision 21 and the M3 "API conventions and compatibility policy" item

## Context
M3 builds the first tenant-owned business tables, so several small decisions arrive together: how the
tenant reaches PostgreSQL for row-level security, how database tests run when Testcontainers cannot reach
the Docker engine inside WSL (Open Decision 21), how lists are paged, how the API is documented and
protected from breaking changes. Each is too small for its own ADR; they share one review.

## Decision
1. **RLS wiring (ADR-0011 applied).** Every tenant-owned unit of work starts with
   `TenantScopedTransaction.BeginAsync(database, tenantId)` (`BuildingBlocks.Persistence`): a transaction whose
   first statement is `set_config('app.tenant_id', @tenant, true)`. Policies compare `tenant_id` with
   `nullif(current_setting('app.tenant_id', true), '')::uuid`: after a transaction that set the value, a
   pooled connection reads an empty string rather than null, and `nullif` keeps that fail-closed instead of
   an invalid-uuid error. Tables are `ENABLE` + `FORCE ROW LEVEL SECURITY`, with `USING` and `WITH CHECK`.
   The tenant id comes from `ITenantContext`, never from the route.
2. **Database tests.** The Compose PostgreSQL stays the local database for tests (`dev.ps1 db-tests`).
   Testcontainers PostgreSQL (`Testcontainers.PostgreSql`, test project only) is the CI path on Linux, where the
   Docker socket is reachable: an assembly fixture starts the Compose image (same digest) and provisions the same two
   roles, but only when `TENANTFLOW_TEST_CONTAINER=1` is set and no Compose settings are present. Without either, the
   run still fails with instructions (SPEC-0002 criterion 4). It cannot run on this workstation, so it is verified
   only when CI runs. Cost: one test-only package and a second path that is unproven locally.
3. **Pagination is keyset (cursor).** Lists order by a unique key (`sku`, `id`), take `limit` (default 20,
   maximum 100) and an opaque `cursor`, and return `nextCursor`. Stable under concurrent inserts; no deep-offset cost.
   The cost: no random page access, and the cursor format is a contract once published.
4. **OpenAPI** is generated by `Microsoft.AspNetCore.OpenApi` (in the framework from .NET 9, carried to .NET 10).
   A test compares the generated document to the committed `docs/api/openapi-v1.json`; any change fails until the
   snapshot is updated deliberately (`TENANTFLOW_UPDATE_OPENAPI_SNAPSHOT=1`) in the same change. The document is
   served at `/openapi/v1.json` only when `ApiDocumentation:Enabled` is true (Development, and the contract test), so
   a deployed API does not publish its route map by default. Tenant routes document 401, 403 and 404 Problem Details
   once, in `RequireTenantPermission`; each route adds its own 400, 409 or 412.
5. **Compatibility policy for `/v1`.** Allowed without a new version: new endpoints, new optional request
   fields, new response fields, new error codes on new failure paths. Breaking, so `/v2`: removing or renaming
   a field, route, or error code; changing a type, a required-ness, a status code, or a pagination or ordering
   rule. Clients must ignore unknown response fields.
6. **Permission names are a contract.** They live in `IdentityAccess.Contracts.TenantPermissions`, so a module that
   checks `ITenantContext.HasPermission` and the host that declares a route's permission use one definition; the
   role-to-permission table stays inside IdentityAccess.
7. **Boundaries are tested, not reviewed.** `tests/Architecture` reads each compiled module assembly's references:
   another module only through `Contracts`, layers inward only, no EF Core, Npgsql or ASP.NET Core outside
   Infrastructure, and each `DbContext` mapping only its own schema. Reflection only, no package.

## Options considered
- **Compose locally, Testcontainers in CI (chosen)** vs Compose only (gate wording unmet) vs running tests inside
  WSL (second SDK, slower setup).
- **Keyset (chosen)** vs offset: offset is simpler for clients but unstable under writes and slow on deep pages.
- **Built-in OpenAPI (chosen)** vs Swashbuckle/NSwag: extra dependency for features one version does not need.

## Consequences
- Easier: a missed tenant filter returns nothing instead of another tenant's data; a breaking API change fails a test.
- Harder: every tenant-owned write path must use the scoped transaction; snapshot updates are a deliberate step.

## Validation
`RowLevelSecurityTests` (isolation, no tenant, pooled leak, forced RLS); the OpenAPI snapshot test and the
pagination criteria of SPEC-0003; the Testcontainers fixture is proven when CI first runs it.

## Revisit triggers
Measured policy overhead in query plans; Docker Desktop or an exposed loopback daemon becomes available locally;
the need for deprecation headers (adopt Asp.Versioning at the .NET 10 move, see ADR-0015).
